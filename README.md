# Системный Детектив — публикация в интернете

Интерактивное пособие по Системно-Векторной Психологии Юрия Бурлана. Всё лежит в одном файле `index.html` (около 460 КБ): никаких сборщиков, зависимостей и локального сервера для просмотра. Шесть иллюстраций вшиты внутрь файла как WebP в base64, поэтому рядом с `index.html` ничего класть не нужно.

## Что нужно знать до публикации

- **Страница станет публичной.** Любой, у кого есть ссылка, сможет её открыть. На бесплатном GitHub Pages это значит ещё и то, что исходники репозитория видны всем.
- **Интернет нужен только для шрифтов и иконок.** Tailwind CSS скомпилирован и встроен в `<style>` (13 КБ), FOUC и задержка компиляции в браузере исчезли. FontAwesome и шрифты Onest/Manrope остались на CDN: без сети страница откроется, но иконки и шрифт заменятся на системные. Иллюстрации лежат внутри файла.
- **Данные внутри.** Никаких форм, отправки заявок и внешних запросов: страница ничего никуда не передаёт. Кнопка «Поделиться результатами» копирует текст в буфер обмена, системное «Поделиться» вызывает `navigator.share` телефона.
- **Папка `assets/img`** рядом лежит как исходник иллюстраций: на работу страницы она не влияет, в публикацию её класть не нужно.
- **Двойным кликом тоже работает.** Открыть `index.html` из проводника можно без хостинга вообще — так удобно проверять правки до выкладки.

## Правовой статус и позиция по тестам

- **Методология.** Пособие опирается на фундаментальную методологию системно-векторной психологии Юрия Бурлана. Термины, свойства и описания векторов взяты с открытого портала `yburlan.ru`, где собраны лекции, тренинги и открытые материалы метода. Методология передаётся через лекции, многочасовые тренинги и устный психоанализ.
- **Формат.** «Системный Детектив» — самостоятельный независимый эдьютейнент-проект: интерактивные игры, симуляторы и бизнес-кейсы по методу. Официальный портал и школа к этому формату отношения не имеют.
- **Ответственность.** За формат подачи, игровые механики и возможные неточности отвечают создатели сайта. Методология, её термины и полный векторальный набор остаются за автором, порталом и обучающими специалистами.
- **Тест — игровая метафора.** Детектив показывает направление желаний в игровой ситуации и предлагает копать глубже. Клинического диагноза, приговора и готового ярлыка он не ставит: полный векторальный набор определяют специалисты в процессе обучения.

Эти же оговорки продублированы на странице: в шапке раздела «Системный Детектив», в блоке «Методология и формат», в подвале и в текстах отчётов, которые уходят при шеринге.

## Общая комната: общий сервер и публикация картинок

Секция «Общая комната» в конце пособия позволяет каждому гостю выложить свою картинку (фото, гифку, открытку) и поставить её в комнате перетаскиванием. Картинки хранятся в общем хранилище, поэтому их видят все посетители. Есть кнопки «Скачать PNG» (собирает комнату в файл), кнопка удаления своих неопубликованных картинок и согласие на публичный показ.

Чтобы общая комната работала, нужен маленький сервер: статическая страница сама по себе не умеет хранить то, что прислали посетители.

**Что уже готово в репозитории**

- `server/worker.js` — Worker: приём картинок, выдача списка, отдача файлов, удаление, лимиты.
- `server/wrangler.toml` — конфигурация публикации.
- `server/deploy.sh` — публикация одной командой.
- `server/test-worker.mjs` — тесты сервера: 49 проверок, гоняются локально без интернета.
- `server/local-server.mjs` — запуск того же кода локально, для проверки фронта.

**Как опубликовать**

```bash
cd server
npx wrangler login          # откроется браузер, нажмите Allow
bash deploy.sh              # создаст хранилище, спросит секрет, опубликует Worker
```

Скрипт создаёт пространство KV, сам генерирует секрет оператора `ROOM_ADMIN_TOKEN` (это ключ, которым удаляются неуместные предметы), печатает его один раз и публикует Worker. В конце печатается адрес вида `https://svp-room.<поддомен>.workers.dev`.

Этот адрес вписывается в страницу одной строкой: в самом низу `index.html` найдите `var ROOM_API = "";` и вставьте адрес между кавычками. Пока строка пустая, раздел честно пишет, что комната ждёт подключения сервера, и ничего никуда не отправляет.

**Что защищено на сервере**

- Определение формата по сигнатуре файла, а не по заявленному клиенту: svg и подделки отсеиваются. Полиглотные файлы отдаются с `nosniff` и браузером не исполняются.
- Ограничение 8 МБ на картинку, 300 предметов в комнате и 10 загрузок в сутки с одного адреса. Счётчик загрузок живёт в Durable Object, поэтому пачка параллельных запросов лимит не обходит.
- Удаление доступно по секрету администратора или по личному ключу, который гость получает при публикации и может снять свою картинку сам. Полный список предметов для модерации: `GET /admin/items` с секретом оператора.
- Перебор секрета оператора ограничен: после двенадцати неудачных попыток с одного адреса запросы отбиваются.
- Идентификаторы проверяются по шаблону, обход пути не проходит.
- Список комнаты кэшируется в Worker на 10 секунд, поэтому опрос раз в 12 секунд не съедает лимиты KV. Сама картинка отдаётся одним чтением, без списка ключей.
- Картинки с EXIF-метаданными сервер не принимает, а форма вычищает их до отправки: координаты из телефона в общую комнату не попадают.
- Предмет живёт в комнате 30 дней, потом исчезает сам.

**Что стоит знать про хранение**

Картинки лежат в KV-хранилище Cloudflare, то есть за пределами России. Для учебного проекта с добровольными публичными картинками это рабочий вариант, но если в комнате появятся личные данные, смотреть в сторону хранилища в российском регионе.
**Что важно знать про работу**

- У KV и Durable Object на бесплатном плане жёсткие лимиты: около 1000 записей и 1000 списков в сутки, 100 тысяч чтений. Картинка гость читает один раз и дальше берёт её из кэша браузера, для десятков гостей в день этого хватает; при росте нагрузки нужен платный тариф.
- KV сходится не мгновенно: картинка может появиться у других посетителей с задержкой до минуты. Автор сразу видит свой предмет.
- Через форму картинка пережимается и очищается от EXIF с GPS. Прямая загрузка через API с метаданными отбивается.
- Черновик, который ещё не опубликован, живёт до перезагрузки страницы.
- Гость выбирает свой вектор сам, в форме. Раньше подпись подставлялась из открытого дела, и это путало.

## Что внутри страницы

- «Системный Детектив»: три вопроса по сорванной сделке, крупный лид с доминантным вектором, детали в аккордеонах и кнопка «Подобрать пару», которая подставляет ваш вектор в пасьянс.
- «Пасьянс Отношений»: выбор двух векторов из восьми, разбор пары по правилу кварталей, мягкая смена пары с затуханием. На телефоне выбор свёрнут в компактные переключатели, текущая пара висит липкой строкой.
- «Атлас 8 векторов»: карточки всех восьми векторов с желанием, свойствами, проявлением, ресурсом и ценой силы, плюс указатели-стрелки для быстрого перехода.
- Тултипы на пятнадцати терминах системы (квартали, комплементарность, контрарность, нехватки, темперамент) — по мыши и по клавиатуре, Enter и пробел переключают подсказку.
- Мобильное меню: на телефоне в шапке появляется кнопка с полосками, которая открывает список разделов.
- Кнопка «Поделиться результатами» в детективе и в пасьянсе: копирует готовый текст отчёта, рядом ссылка «Показать текст» открывает окно с текстом и системным «Поделиться».
- «Общая комната»: гости выкладывают свои картинки в общую сцену, перетаскивают их мышью, пальцем и стрелками с клавиатуры, сохраняют комнату в PNG, а свою картинку могут снять кнопкой на ней. Работает вместе с сервером из папки `server/`.

## Вариант A. GitHub Pages (бесплатно, навсегда)

Аккаунт пользователя: `registracia046-ux`.

### Через веб-интерфейс (5 минут, без терминала)

1. Откройте `https://github.com/new` → имя репозитория, например `svp-detective`. Галочку «Add a README file» можно не ставить.
2. На странице репозитория: **Add file → Upload files** → перетащите `index.html` → **Commit changes**.
3. **Settings → Pages → Build and deployment → Source: Deploy from a branch**, ветка `main`, папка `/ (root)` → **Save**.
4. Через минуту-полторы сайт поднимется: `https://registracia046-ux.github.io/svp-detective/`
   (точный адрес страница покажет сама в разделе Pages).
5. Домен `registracia046-ux.github.io` привязывается к репозиторию через файл `CNAME` в корне — это отдельный шаг, он не обязателен.

### Через терминал

```bash
cd projects/svp-detective
git init -b main
git add index.html
git commit -m "Системный Детектив: пособие по СВП"
git remote add origin https://github.com/registracia046-ux/svp-detective.git
git push -u origin main
```

Дальше — те же шаги 3–4 в настройках репозитория.

### Грабли GitHub Pages

- **Репозиторий должен быть публичным** на бесплатном тарифе. Приватный репозиторий Pages не покажет, даже если включён.
- **Jekyll ломает файлы с подчёркиванием в имени.** Здесь такого нет, но положите пустой файл `.nojekyll` в корень репозитория — Pages перестанет прогонять Jekyll и ничего не испортит.
- **Обновление = заменить `index.html` и закоммитить.** Сборка занимает 30–60 секунд. Если страница не обновилась — жёсткая перезагрузка (`Ctrl+Shift+R`), CDN отдаёт старую версию из кэша.
- **Токен.** Если публикуете скриптом через REST API, токен хранится в секрет-хранилище как `GITHUB_TOKEN` и используется как переменная окружения. Не вставляйте его в код и не логируйте. Токен, попавший в открытую переписку, стоит отозвать и перевыпустить с узким набором прав (`repo` + `pages`).

## Вариант B. Vercel (бесплатно, без правки кода)

### Терминал

```bash
npm i -g vercel
cd projects/svp-detective
vercel            # preview
vercel --prod     # боевой адрес
```

При первом запуске Vercel спросит логин (email + код) и папку проекта. Ответьте `Y` на вопрос про перенастройку команды сборки. Framework Preset: **Other**, Output Directory: `.`, Install/Build Command: оставить пустыми — собирать нечего.

### Без терминала

1. Откройте `https://vercel.com/new` → **Add New → Project**.
2. Импортируйте репозиторий с GitHub (или загрузите папку через `vercel deploy`).
3. Оставьте настройки сборки пустыми, нажмите **Deploy**.
4. Адрес: `https://svp-detective.vercel.app` (своё поддомен можно поменять в Settings → Domains).

Обновление при новом коммите в GitHub — автоматически, за минуту.

## Вариант D. Свой сервер

### Nginx

```bash
scp index.html user@server:/var/www/svp-detective/index.html
```

```nginx
server {
    listen 80;
    server_name svp.example.ru;
    root /var/www/svp-detective;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

### Apache

```apache
<VirtualHost *:80>
    ServerName svp.example.ru
    DocumentRoot /var/www/svp-detective
    <Directory /var/www/svp-detective>
        Require all granted
    </Directory>
</VirtualHost>
```

### Проверка без домена

```bash
cd /var/www/svp-detective && python3 -m http.server 8000
```

## Что проверить сразу после публикации

1. Страница открылась, вкладка называется «Системный Детектив», фон тёмный, шрифты загрузились.
2. **«Начать расследование»** открывает детектив: три вопроса, на выходе вектор и разбор. Кнопка «Пройти заново» сбрасывает сценарий.
3. **«Пасьянс Отношений»**: выбор двух векторов даёт мгновенный разбор, повторный выбор того же вектора меняет слоты местами.
4. **«Поделиться результатами»** кладёт текст в буфер (кнопка коротко пишет «Скопировано»), **«Показать текст»** открывает окно с готовым текстом отчёта.
5. **Тултипы**: наведите курсор на подчёркнутые термины («квартали», «комплементарность» и др.) — появится объяснение. С клавиатуры: `Tab` до термина, `Enter` не нужен, подсказка видна по фокусу, `Esc` закрывает.
6. **Мобильный вид**: откройте страницу на телефоне, прокрутите до пасьянса — горизонтальной прокрутки нет, кнопки нажимаются.
7. **Консоль без ошибок**: `F12 → Console` — пусто. Если есть ошибки загрузки CDN, значит у хостинга или посетителя закрыт внешний доступ — страница покажется без стилей.

## Если нужно пересобрать Tailwind

Tailwind лежит в файле готовым CSS. После правки классов в разметке пересобери его:

```bash
npm install tailwindcss@3.4.19
./node_modules/.bin/tailwindcss -c tailwind.config.js -i input.css -o out.css --minify
```

Конфиг и входной файл лежат в `/workspace/build/tw/`. Готовый `out.css` вставляется в `<style id="tailwind">` в `index.html` сразу после блока кастомных стилей, а `<script src="https://cdn.tailwindcss.com">` из `<head>` убирается.

## Обновление

Везде правится один и тот же файл: меняете `index.html` локально, проверяете двойным кликом или локальным сервером, затем заливаете тем же способом, каким публиковали (перетащить файл, `git push`, `vercel --prod`, `scp`).

Для GitHub Pages и Vercel после привязки GitHub обновление происходит автоматически по коммиту. На Netlify — то же самое.
